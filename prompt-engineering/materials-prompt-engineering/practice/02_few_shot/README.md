# Lesson 02 — Few-shot prompting

## Concept
Examples act as behavioral specifications. One example is one-shot prompting; several are few-shot prompting.

## Why it works
Well-chosen demonstrations define label boundaries and special cases more concretely than repeated prose.

## When to use it
Use examples when categories are unfamiliar, ambiguous, or have important edge cases.

## When not to use it
Do not spend context on five redundant easy examples when two contrasting examples teach the boundary.

## Common failure modes
Examples can be copied too literally, teach accidental patterns, or omit the difficult case that matters.

## Exercise
Classify each support request as `billing`, `technical`, `account`, or `other`. Improve the prompt with a small, diverse example set.

## What to observe
Compare five easy examples with two examples covering missing detail and an ambiguous request.
